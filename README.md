# Омега Комплект

Адаптивный сайт ООО «Омега Комплект» с подбором ленточных полотен, разделом станков и рольгангов, модальной заявкой, маской телефона, контактами, доставкой, политикой обработки данных, отдельным согласием и настройками cookie. Палитра № 4 зафиксирована в ПАЛИТРА.md.

Шрифт — **Golos Text**, локальный файл с кириллицей и лицензией SIL OFL 1.1. [Шкала крупной типографики](docs/typography-2026-10-15.md) общая для сайта, форм и документов.

Блок «Все, что нужно для точного реза» — [интерактивная витрина преимуществ](docs/interactive-benefits-2026-10-15.md): четыре переключателя, фото, плавная смена контента, реакция на курсор и свайпы. Автопереключения нет. `npm run verify:benefits` проверяет управление и адаптивность без отправки заявок.

## Почтовая форма

Подготовлена для PHP-хостинга в РФ и SMTP Mail.ru: **omegakomplekt@mail.ru**, smtp.mail.ru:465, TLS. Адрес посетителя — Reply-To. Пароль не находится в браузере или репозитории. Отправка пока выключена, реальные заявки и SMTP-доставка не проверялись и письма не отправлялись.

Для подключения позже нужны пароль внешнего приложения Mail.ru и домен хостинга. [Инструкция подключения](docs/CONNECT-SMTP.md) описывает структуру папок, настройки и требования. Успех в интерфейсе показывается только после подтверждения серверного обработчика; ошибка сохраняет введённые данные.

Встроенная форма отправляет заявку напрямую через тот же PHP-обработчик: параметры, контакты и отдельное согласие находятся в самой форме. Остальные кнопки заявки открывают модальную форму. Обе формы используют общую валидацию, маску и защиту от повторной отправки; открытие модалки не отправляет данные.

Секция формы компактная; необязательные имя и компания раскрываются по клику. Ошибки поясняют, что исправить, выделяют поле и собираются в список с переходами. [Подробности и замеры](docs/compact-validation-2026-10-15.md). `npm run verify:validation` проверяет только локальную валидацию без отправки формы и обращений к API.

[Раздел оборудования](docs/equipment-2026-10-15.md) сравнивает станки с гидроразгрузкой, полуавтоматические и автоматические; рольганги представлены отдельно. Для каждой категории использовано каталожное фото PILOUS, локальные WebP оформлены в монохромной гамме сайта. [Источники изображений](docs/assets.md). Кнопки открывают заявку с выбранной категорией. Черновики параметров полотен и каждой категории оборудования сохраняются раздельно. Проверка `npm run verify:equipment` не отправляет заявки.

## Структура

- `dist/` — HTML, CSS, JavaScript, локальные фото и шрифты; статический просмотр сайта.
- `php/public_html/api/request.php` — публичный PHP endpoint.
- `php/private/` — обработчик, настройки-пример и PHPMailer 7.1.1; размещается вне публичного корня.
- `scripts/` — локальный просмотр, генерация юридических страниц, сборка и проверки.
- `docs/` — инструкции и история решений. Актуальная отправка: mail-preparation-2026-10-14.md.
- `wordpress/omega-komplekt/` — самостоятельная классическая тема WordPress; установка и контракты плагина описаны в её [README](wordpress/omega-komplekt/README.md).

Собрать для хостинга: `npm run build:hosting`. В `release/hosting` появятся `public_html`, соседняя `private` и инструкция. Загрузка `dist` на GitHub Pages или статический хостинг не запускает PHP. Пакет содержит библиотеку почты, Composer не требуется. PHP 8.1+, OpenSSL, session и HTTPS обязательны.

Копия `php/private/mail.example.php` → `private/mail.local.php` на сервере. Указать пароль приложения, точный HTTPS-origin и включить `enabled`. Настоящая конфигурация, сессии и сборки исключены из Git и архивов исходников. Никаких проверочных POST/писем без отдельного разрешения заказчика.

## Локальный просмотр

`npm run dev`, затем http://127.0.0.1:4173. Установка зависимостей для самого сайта не нужна. Этот сервер показывает интерфейс и не исполняет PHP.

## GitHub Pages

Сайт: **https://rez1dennt.github.io/omega/**. В Settings → Pages → Build and deployment выбран **GitHub Actions**. Workflow `.github/workflows/pages.yml` публикует содержимое `dist/` при изменении сайта в `main`; его можно запустить вручную через Actions → Deploy website to GitHub Pages → Run workflow. Корень репозитория с README не публикуется.

GitHub Pages показывает статический интерфейс. Для отправки заявок необходим PHP-хостинг из раздела «Почтовая форма»; SMTP остаётся выключенным до подключения. Workflow не запускает PHP и не содержит почтовых секретов.

Проверка путей проекта перед публикацией (PowerShell):

```powershell
$env:PORT='4174'
$env:BASE_PATH='/omega'
npm run dev
```

В другом терминале: `npm run verify:pages`. Проверяются главная, политика и согласие по адресу `/omega/`, ресурсы, модули и интерфейс на 1280, 768, 360 и 320 px. Можно указать другой адрес через `BASE_URL` с завершающим `/`. Проверка блокирует обращения к API и любые отправки форм.

## WordPress

Текущая тема — **1.4.0**, с актуальными телефонами, неприводными рольгангами и непрерывным подбором труб: [методика LENOX, источники и рабочий диапазон](docs/continuous-pipe-pitch-2026-10-21.md). Справочники компании и BAHCO, общая сетка оборудования и компактная плашка IDEAL сохранены.

`npm run build:wordpress` собирает **`../omega-komplekt-wordpress-theme.zip`** с одним каталогом `omega-komplekt/`. Этот ZIP устанавливается через «Внешний вид → Темы → Добавить новую → Загрузить тему». Требования: WordPress 6.6+, PHP 8.1+; ACF и конструктор для отображения не нужны.

Главная разделена на секции, данные — в `data/*.php`, общие элементы и формы — в `template-parts/`, подключение ресурсов/документов/будущего плагина — в `inc/`. Тема использует `wp_head`, `wp_body_open`, `wp_footer`, штатные enqueue API и import map; учитывает панель администратора и дочерние темы. Активация не создаёт и не меняет контент. Статическая публикация `dist/` остаётся отдельной.

Полное редактирование WordPress реализовано отдельным плагином **«Омега — Настройка сайта»** на ACF PRO: 26 разделов с заполненными текстами, фотографиями, иконками, действиями кнопок, документами и таблицами. [Памятка клиенту](wordpress/НАСТРОЙКА-САЙТА.md), [архитектура темы](wordpress/omega-komplekt/README.md), [контракт плагина](wordpress/plugins/omega-site-settings/README.md). Сборка собственного плагина: `npm run build:wordpress-plugin`. Коммерческий ACF устанавливается отдельно. Для переноса изменённого контента нужны также база данных и uploads. Отправка заявок подключается отдельным плагином: тема не содержит SMTP, паролей, PHPMailer или endpoint по умолчанию. Без JavaScript формы не отправляют персональные данные нативным GET.

Для разработки: `npm run prepare:wordpress`, затем `npm run dev:wordpress`; в другом терминале `npm run verify:wordpress`. В изолированном `qa/wordpress` скачиваются официальные WordPress и SQLite integration только для тестирования. QA блокирует почту и все HTTP-методы, кроме GET/HEAD. Рабочий MySQL/MariaDB-хостинг для темы не заменяется этим тестовым окружением. Проверить точный ZIP можно, установив `OMEGA_WP_THEME_ZIP` в его абсолютный путь перед `verify:wordpress`.

## Проверки

`npm run verify`, `verify:typography`, `verify:modal`, `verify:polish`, `verify:dropdown`, `verify:mail`. Browser-проверкам нужен Playwright в node_modules или путь CODEX_NODE_MODULES. По указанию заказчика проверки не нажимают окончательную отправку и не тестируют доставку. PHP проверяется `php -l`. QA-скриншоты и отчёты не попадают в Git.

## Документы и данные

Политика — `/privacy/`, согласие — `/consent/`; источник и общий шаблон в `scripts/render-legal.mjs`, генерация `npm run render:legal`. Cookie-настройки хранят только локальный выбор на 180 дней; собственные счётчики аналитики и рекламные пиксели не подключены. Внешний виджет Яндекс Карт описан в политике и настройках cookie. PHP-сессия нужна для CSRF и защиты от повторных обращений. Компании необходимо соблюдать фактические сроки, доступы и обязанности оператора; код не заменяет организационные меры.

Контакты и реквизиты перенесены из документа компании и доступны в постоянной секции `#contacts` на главной странице. Встроена настоящая Яндекс Карта проверенного здания: Саратов, Большая Садовая, 141; в адресе указан офис 314. [Подключение карты и проверки](docs/contacts-map-2026-10-15.md). Фотоиллюстрации услуг созданы ImageGen; фото оборудования взяты из каталога PILOUS. Перед клиентским запуском подтвердить фактические сроки изготовления/сварки, фото и домен. Цвета в ПАЛИТРА.md используются всеми страницами.

Мобильное меню и диалоги используют общую блокировку прокрутки и сохранение фокуса. Компактный режим учитывает узкий или короткий экран и Visual Viewport. Проверка: `npm run verify:mobile-overlays`; [описание поведения и проверки](docs/mobile-overlays-2026-10-15.md).

Раздел `#pitch-guide` перед формой содержит оцифрованную таблицу шага зуба из фотографии заказчицы: 11 диапазонов прутка, 120 клеток труб (14 пустых), локальный поиск и перенос выбранного TPI в заявку. Источник данных — `dist/scripts/pitch-data.js`; HTML регенерируется `npm run render:pitch`. Проверки: `verify:pitch-data` и `verify:pitch`. [Поведение и ограничения](docs/tooth-pitch-guide-2026-10-16.md).
