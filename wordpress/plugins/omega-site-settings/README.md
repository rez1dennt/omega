# Омега — Настройка сайта

Плагин связывает контент темы `omega-komplekt` с ACF PRO. В меню WordPress появляется один пункт **Настройка сайта**. Сначала выбирается категория, затем раздел; каждый раздел имеет собственную стандартную страницу ACF и кнопку **Сохранить раздел**. Это ограничивает размер отдельной отправляемой формы и снижает риск превышения `max_input_vars`.

Поиск над формой находит поля по русским названиям и переводит к нужному полю, раскрывая его группу. Поля не исключаются из сохранения при поиске. В разделе иконок готовый символ показан рядом со списком и обновляется при выборе; собственные изображения имеют обычный предпросмотр медиатеки ACF.

## Установка и первичное заполнение

1. Установите ACF PRO отдельно и активируйте его. Лицензионные файлы ACF в комплект этого плагина не входят.
2. Скопируйте каталог `omega-site-settings` в `wp-content/plugins/` и активируйте плагин. Тема `omega-komplekt` должна быть доступна, чтобы импортировать её исходные изображения.
3. Откройте **Настройка сайта → Первичное заполнение текущим контентом** и нажмите **Заполнить текущим контентом**.
4. Дождитесь последовательного заполнения разделов и обновления страницы. Проверьте изображения в медиатеке и сохраните нужные изменения обычной кнопкой ACF.

Заполнение происходит только после явного нажатия кнопки администратором. Активация, просмотр сайта и открытие админки ничего не импортируют и не сбрасывают. Повторный запуск добавляет только отсутствующие значения, включая новые поля внутри существующих групп и строк. Сохранённые пустые строки, нули, выключенные переключатели, пустые списки и выбранные ID файлов сохраняются. При ошибке процесс останавливается с сообщением; его можно запустить снова. Не закрывайте окно во время заполнения. Перед запуском сохраните несохранённые правки текущего раздела.

## Контракт данных

Каждый локальный `config/*.php` возвращает массив:

```php
array(
    'section' => array(
        'title' => 'Название раздела',
        'fields' => array(
            'title' => array( 'type' => 'text', 'label' => 'Заголовок', 'default' => 'Исходный текст' ),
        ),
    ),
);
```

Поддерживаются обычные настройки ACF прямо в дескрипторе или в `args`, а также вложенные `fields` для `group` и `repeater`. Поля `accordion`, `tab` и `message` управляют только отображением и не попадают в публичные данные. Имена полей не зависят от их русских подписей. Корневая группа имеет имя `omega_<section>` и ключ `field_omega_<section>`; ключи потомков строятся по стабильному пути с разделителем `__`. Не переименовывайте существующие имена и ключи при смене подписей.

Все страницы используют ACF `post_id = omega_site`. Публичный snapshot хранится в отдельной опции `omega_site_settings_public` и обновляется после сохранения ACF и первичного заполнения. Он содержит исходные массивы и ID медиа, а не HTML. Если ACF отключён, сайт продолжает читать snapshot; административное уведомление объясняет необходимость ACF PRO для правок.

Внутренние ключи ACF в сырых значениях групп и повторителей преобразуются в стабильные имена полей без форматирования самих значений. Пустой числовой предел, заданный в исходной схеме как `null`, сохраняется пустой строкой: ACF пропускает несохранённые `null` при обновлении группы. Это сохраняет идемпотентность заполнения; таблицы по-прежнему содержат `null` в ячейках «нет данных».

- `omega_site_settings_schema()` — загруженная локальная схема.
- `omega_site_settings_values($section)` — значения раздела: исходные значения схемы с поверхностной заменой сохранённым snapshot. Пустые значения учитываются; ID медиа остаются ID.
- `apply_filters('omega_site_settings', $defaults, $section)` — поверхностное наложение snapshot на переданные исходные значения.
- `omega_site_settings_seed_section($section)` — явное заполнение недостающих полей; требует `manage_options` и активный ACF PRO. Возвращает результат либо `WP_Error`.
- `omega_site_settings_refresh_snapshot()` — перечитывает сохранённые разделы ACF в публичную опцию.
- `omega_site_settings_media_url($value)` — разрешает ID или доверенный путь исходного медиа в URL без импорта.

Адаптер `omega_theme_content` разрешает поля `image`/`file` в URL для старых плоских шаблонов темы. Для компании `phone_uri` и `office_phone_uri` вычисляются из соответствующих отображаемых телефонов; отдельных редактируемых полей `tel:` нет. Новые шаблоны получают ID через raw-контракт и используют обычные функции медиатеки WordPress.

## Изображения и безопасность

Исходный файл в дескрипторе `image`/`file` задаётся как `assets/...` внутри текущей темы либо `plugin:assets/defaults/...` внутри плагина. Импорт не скачивает произвольные URL и не принимает пользовательский путь к файлу. После `realpath` проверяется принадлежность разрешённому каталогу. Исходный файл копируется во временный; `media_handle_sideload` работает только с этой копией. SHA-256 в метаданных вложения защищает от повторного импорта, а блокировки ограничивают параллельные запуски. `alt` из дескриптора записывается при первом импорте, существующие пользовательские изображения и их метаданные не перезаписываются.

Для SVG действует отдельная строгая проверка через `DOMDocument` с `LIBXML_NONET`: запрещены DTD, сущности, инструкции обработки, скрипты, обработчики событий, `foreignObject`, внешние ссылки, активные CSS и неподдерживаемые элементы. Допуск SVG MIME существует только на время импорта проверенной временной копии и снимается в `finally`. Общая загрузка SVG пользователями не включается.

AJAX-заполнение принимает только POST, требует `manage_options` и nonce; импорт файлов дополнительно требует `upload_files`. Входные значения ACF проверяются и очищаются по типу. Публичные шаблоны по-прежнему должны экранировать текст, атрибуты, ссылки и HTML по месту вывода. В runtime JSON не должны попадать пароли, SMTP-конфигурация или закрытые ключи: этот плагин не читает и не меняет их.

Удаление или отключение плагина не удаляет опции и вложения. Не предусмотрено автоматического сброса контента. Перед изменением схемы и миграциями сделайте резервную копию базы и `uploads`.
