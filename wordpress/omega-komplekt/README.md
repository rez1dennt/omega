# Тема «Омега Комплект» 2.1

Классическая тема для WordPress 6.6+ и PHP 8.1+. Текущий дизайн, адаптивность, формы и локальные ресурсы сохранены. Для отображения исходного сайта дополнительные плагины не нужны. Для редактирования всего содержимого установите **ACF PRO** и собственный плагин **«Омега — Настройка сайта»**.

## Установка

1. Загрузите `omega-komplekt-wordpress-theme.zip` через **Внешний вид → Темы → Добавить тему**, активируйте тему.
2. Активируйте отдельно приобретённый ACF PRO.
3. Загрузите `omega-site-settings-wordpress-plugin.zip` через **Плагины → Добавить плагин** и активируйте.
4. Откройте **Настройка сайта → Первичное заполнение текущим контентом → Заполнить текущим контентом**. Дождитесь окончания. Поля и медиатека заполняются текущим содержимым сайта.

На подготовленном локальном сайте `omega` эти действия уже выполнены. Для переноса изменённого контента на другой WordPress переносите также базу данных и `wp-content/uploads`: ZIP содержит код и исходное заполнение, а пользовательские изменения хранятся в WordPress.

## Редактирование

В меню **Настройка сайта** доступны 26 вкладок. Выберите раздел, раскройте нужную группу, измените значение и нажмите **Сохранить раздел**. Каждая вкладка сохраняется отдельно. Перед переходом к другой вкладке сохраните правки. Пустое сохранённое поле остаётся пустым.

Редактируются все тексты и подписи главной, шапка и подвал, фотографии и описания, логотипы и favicon, иконки и декоративные изображения, действия кнопок, формы и их сообщения, карта, контакты, скачиваемые реквизиты, Cookie, документы и справочники шага зуба. Визуальный редактор документов поддерживает абзацы, списки и ссылки. Матрицы имеют обычные ячейки, кнопки добавления диаметра/толщины и проверку значений.

Общие телефоны и почта задаются во вкладке **Компания и реквизиты**. Ссылки `tel:` формируются автоматически. Выбранная фотография первого экрана используется также в фоне и preload. Менять исходники для этих действий не требуется. Обычные дополнительные записи и страницы редактируются штатным редактором WordPress.

## Архитектура

| Путь | Назначение |
| --- | --- |
| `functions.php`, `inc/setup.php` | Запуск темы, WordPress hooks, title/meta, preload и favicon |
| `inc/editor.php` | Безопасный вывод ACF-значений, медиа, иконок, действий кнопок, реквизитов и документов |
| `inc/content.php`, `data/*.php`, `data/editor-defaults.json` | Исходные значения и совместимый контракт секций |
| `inc/pitch.php`, `data/pitch-data.json` | Единые данные PHP/JS и варианты TPI |
| `inc/assets.php` | CSS/JS, зависимости, версии и публичный runtime-конфиг |
| `template-parts/` | Шаблоны секций, форм, окон и документов |
| `inc/documents.php` | Query/native URL документов, canonical и проверка маршрута |
| `inc/integrations.php` | Публичный контракт отдельного обработчика заявок |

Поля, options pages, импорт медиа, первичное заполнение и публичный snapshot находятся в отдельном плагине `omega-site-settings`. Коммерческие файлы и лицензия ACF в комплект не входят. Отключение ACF сохраняет вывод уже заполненного snapshot; редактирование требует ACF PRO. Отключение собственного плагина возвращает исходные данные темы.

`omega_theme_settings($section, $defaults)` получает raw значения через фильтр `omega_site_settings`. Медиа остаются attachment ID до границы вывода. Строки/атрибуты/URL экранируются по месту использования. Обычные текстовые поля не исполняют HTML. Документы проходят `wpautop` и ограниченный `wp_kses`. Сохранённые пустые значения не подменяются исходным текстом.

Прежний фильтр `omega_theme_content` сохранён для совместимости. Новые данные доступны через typed helpers темы. Ключи ACF стабильны и не зависят от русских названий полей. Плагины не должны менять файлы темы.

## Формы и документы

Без отдельного плагина отправка выключена: endpoint пустой. Тема и плагин содержимого не включают SMTP или пароль. Для отправки установите и настройте отдельный [плагин заявок](../plugins/omega-request-mail/README.md). Контракт подключения отдельного плагина:

```php
add_filter( 'omega_theme_request_settings', function (): array {
    return array(
        'endpoint' => rest_url( 'omega/v1/requests' ),
        'nonce'    => wp_create_nonce( 'wp_rest' ),
    );
} );
```

Сервер обязан проверять поля, согласие, ограничения частоты и повторы. Публичный nonce не заменяет серверную защиту. Payload: `parameters`, `email`, `phone`, `name`, `consent`, `website`, `requestId`, `consentVersion`. Ответ принятия: `{"ok":true,"status":"accepted","requestId":"тот же UUID"}`. Версию согласия вычисляет `omega_theme_consent_version()` из текущего документа и реквизитов; её можно использовать в отдельном обработчике. Персональные данные не записываются в localStorage, Cookie или URL.

Документы доступны по `?omega_document=privacy` и `?omega_document=consent`. Если опубликованы штатные страницы `privacy`/`consent`, используются их URL. При активном плагине содержимого обе версии выводят единый документ из ACF. Без плагина непустой контент штатной страницы имеет приоритет. Активация темы не создаёт и не меняет записи, страницы, постоянные ссылки или индексацию WordPress.

## Проверки и сборка

В исходном репозитории: `npm run verify:wordpress` проверяет тему в изолированном WordPress; `npm run build:wordpress` собирает тему; `npm run build:wordpress-plugin` собирает собственный плагин. ACF PRO, база, uploads, QA, пароли и зависимости разработчика в архивы не включаются. Проверки форм выполняются без отправки заявок и писем.

В версии 2.1 секция с формой убрана с главной. Кнопки подбора ведут к таблице шага; после выбора TPI открывается форма полотна в окне. В шапке под основным телефоном — e-mail, оба телефона остаются в контактах и подвале.
