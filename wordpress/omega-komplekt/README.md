# Тема «Омега Комплект»

Устанавливаемая классическая тема: WordPress 6.6+, PHP 8.1+. Сборка, ACF, Elementor и дополнительные плагины для отображения не требуются.

## Установка

Внешний вид → Темы → Добавить новую → Загрузить тему → `omega-komplekt-wordpress-theme.zip` → Установить → Активировать. Альтернатива: этот каталог целиком в `wp-content/themes/omega-komplekt/`.

Главная открывается сразу после активации. Если в «Настройки → Чтение» выбрана статическая главная, её адрес также использует `front-page.php`. Тема не создаёт записи, не меняет `show_on_front`, постоянные ссылки, политику конфиденциальности WordPress, индексацию или иные настройки. Проверка поиска и индексации остаётся в штатных настройках WordPress/SEO-плагина.

## Архитектура

| Путь | Ответственность |
| --- | --- |
| `functions.php`, `inc/setup.php` | Bootstrap и штатная поддержка темы |
| `inc/assets.php` | Каскад CSS, зависимости JS, ES module, версии файлов |
| `inc/helpers.php` | URL ресурсов, медиа, контактов, якорей и документов |
| `inc/content.php`, `data/*.php` | Значения по умолчанию и граница будущего плагина контента |
| `inc/documents.php` | Документы без импорта и приоритет опубликованных WP-страниц |
| `inc/integrations.php` | Только публичные параметры транспорта формы |
| `front-page.php`, `template-parts/sections/` | Девять секций главной, отдельные точки расширения |
| `template-parts/shared/` | Шапка, подвал, общий SVG sprite |
| `template-parts/forms/`, `template-parts/overlays/` | Формы, диалоги и Cookie |
| `page-privacy.php`, `page-consent.php` | Шаблоны юридических документов |
| `page.php`, `single.php`, `archive.php`, `search.php`, `404.php`, `index.php` | Штатная иерархия WordPress и вывод обычного контента |
| `styles/`, `scripts/`, `assets/` | Локальные ресурсы и изолированные интерактивные компоненты |

Главная использует данные темы; `the_content()` выводится на обычных страницах/записях. Доступные заголовки, подписи и изображения главной перечислены в `content-map.json`. Техническая таблица TPI остаётся в `scripts/pitch-data.js`; справочные значения не выводятся из произвольных редакторских полей.

Все функции PHP имеют префикс `omega_theme_`. Общие функции JS экспортируются только в `window.OmegaUI`; сценарии секций изолированы. Ассеты и шаблоны допускают override дочерней темой. `inc/*` загружаются из родителя, чтобы не дублировать bootstrap; расширение выполняется WordPress hooks.

Модули таблицы шага подключены через import map WordPress: дочерняя тема может переопределить `scripts/pitch-data.js` отдельно от `scripts/pitch-guide.js`. При копировании `styles/site.css` в дочернюю тему учитывайте относительные URL шрифта и фонового изображения внутри CSS: поправьте их на нужные URL либо скопируйте ресурсы по тем же относительным путям. Для небольших изменений удобнее подключить отдельный CSS после `omega-wordpress`.

## Плагин контента: контракт

В версии 1.1 первый экран разделяет обычную заявку и подбор полотна. `scripts/selection.js` переносит единственный живой `#order-form` и таблицу TPI в окно подбора и возвращает их при закрытии; черновик, согласие, обработчик отправки и идентификаторы сохраняются. Не дублируйте эту форму в плагине. Тексты окна доступны через секцию `selection` в `omega_theme_content`; магнитный станок — через поля `magnetic_*` секции `equipment`. В производстве используется фактическая фотография IDEAL.

Плагин хранит настройки/поля/CPT и возвращает значения темы. Тема не связывается с конкретным плагином полей:

```php
add_filter( 'omega_theme_content', function ( array $content, string $section ): array {
    if ( 'hero' === $section ) {
        $content['paragraph_1'] = 'Актуальное описание компании';
        $content['image_1'] = wp_get_attachment_image_url( 123, 'full' ) ?: $content['image_1'];
    }
    return $content;
}, 10, 2 );
```

`data/company.php` — общие контактные сведения. Для телефона изменяются согласованно `phone` и `phone_uri`. Значения секций — строки; пропущенные или некорректные значения сохраняют встроенный default. Текст выводится с экранированием; HTML в обычных строковых полях не исполняется. Медиа принимает HTTPS/HTTP URL вложения либо относительный путь ресурса темы. Для альтернативной структуры секции дочерняя тема переопределяет соответствующий `template-parts/sections/*.php`.

Actions `omega_theme_before_section` и `omega_theme_after_section` принимают `(string $section, array $content)`; `omega_theme_assets_enqueued` позволяет подключить дополнительные зависимости. Плагины не должны редактировать файлы темы.

## Плагин заявок: контракт

В теме нет SMTP или endpoint по умолчанию. Пустые настройки не вызывают сеть. Кнопки отправки изначально отключены и становятся активны только после установки JS-обработчика; без JavaScript вместо нативной отправки доступны контакты. Плагин регистрирует серверный обработчик, свои проверки и SMTP; тема получает только публичный URL и nonce:

```php
add_filter( 'omega_theme_request_settings', function (): array {
    return array(
        'endpoint' => rest_url( 'omega/v1/requests' ),
        'nonce' => wp_create_nonce( 'wp_rest' ),
    );
} );
```

Это пример подключения уже реализованного endpoint, сам маршрут этой темой не создаётся. Клиент использует same-origin POST JSON и, если указан nonce, заголовок `X-WP-Nonce`. Плагин обязан учитывать анонимных посетителей и кеш страниц: одного nonce недостаточно для защиты публичной формы; серверная проверка согласия/полей, лимитов и повторов остаётся в плагине.

Поля: `parameters`, `email`, `phone`, `name`, `consent`, `website` (honeypot), `requestId`, `consentVersion`. Успех: `{"ok":true,"status":"accepted","requestId":"тот же UUID"}`. Ошибка: HTTP 4xx/5xx с `{"ok":false,"code":"validation_failed","fieldErrors":{"phone":"Введите номер полностью"}}`. Поля и пользовательский комментарий сохраняются при ошибке.

Другой серверный протокол подключается адаптером `window.OmegaThemeRequest = async (payload, {endpoint, nonce, signal}) => result`. Адаптер возвращает тот же подтверждённый ответ; theme client проверяет `requestId`. Скрипт адаптера регистрируется плагином с зависимостью от `omega-request-client`. Ложный успех и автоматические письма посетителю не предусмотрены. Тема не поставляет рабочий серверный обработчик.

## Юридические документы и адреса

Сразу работают `home_url('/?omega_document=privacy')` и `consent`, включая WordPress во вложенном каталоге и plain permalinks. Разрешены только эти два значения. Настоящие опубликованные страницы `privacy`/`consent` получают приоритет в ссылках. Пустая страница выводит встроенный текст, непустая — содержимое WordPress. Произвольному slug можно назначить соответствующий шаблон вручную, после чего ссылки следует настроить будущим плагином.

Перед включением нового обработчика/аналитики документы согласуются с фактической обработкой данных. Индексацию определяет WordPress, жёсткого `noindex` из статической версии в теме нет.

## Проверки и сборка в исходном репозитории

`npm run verify:wordpress` — реальный локальный WordPress и браузерные проверки; `npm run build:wordpress` — ZIP с единственным каталогом `omega-komplekt/`. Подробности подготовки QA-окружения находятся в `scripts/wordpress-fixture.mjs` исходного репозитория; тестовое ядро/SQLite/учётная запись в тему не входят.
