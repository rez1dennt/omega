# Подключение сайта на PHP-хостинге в РФ

Получатель заявок зафиксирован на сервере: **omegakomplekt@mail.ru**. Через форму нельзя изменить адрес получателя. Посетитель указан в Reply-To, чтобы менеджер мог ответить на письмо. Автоматических писем посетителю нет.

Отправка пока выключена: пароль не внесён, SMTP-соединения и тестовые заявки не выполнялись. Для подключения позже достаточно домена хостинга и пароля приложения Mail.ru.

## Размещение

Собрать пакет: `npm run build:hosting`. Папка `release/hosting` содержит:

```text
public_html/                 ← корень сайта, доступный по HTTPS
  index.html
  api/request.php
  assets/, styles/, scripts/, privacy/, consent/
private/                    ← рядом с public_html, вне доступа из Интернета
  mail.example.php
  request-handler.php
  lib/PHPMailer/
CONNECT-SMTP.md
```

Загрузите содержимое public_html в корневую публичную папку домена. private разместите рядом с ней, вне публичного каталога. Если на хостинге другая структура, измените путь `$private` в api/request.php. Не переносите private внутрь публичной папки. Встроенный .htaccess — дополнительная защита для Apache, он не заменяет правильное размещение.

Нужны PHP 8.1 или новее, расширения OpenSSL и session, HTTPS и разрешённое исходящее соединение на smtp.mail.ru:465. Composer не нужен: PHPMailer 7.1.1 уже включён с лицензией. Сервер должен разрешать запись в private/sessions; права только для владельца процесса, без 777.

## Конфигурация

1. Создайте пароль внешнего приложения в почте Mail.ru. Используйте пароль приложения, а не обычный пароль входа. [Инструкция Mail](https://help.mail.ru/mail/login/mailer/).
2. Скопируйте private/mail.example.php в **private/mail.local.php**.
3. В локальном файле укажите `smtp_password` и `site_origin`: точный HTTPS-адрес домена без завершающего слеша, например `https://ваш-домен.рф` в его DNS-представлении.
4. После размещения установите `enabled` в `true`. Сохраните `require_https` равным `true`, SMTP-порт 465, TLS и логин omegakomplekt@mail.ru.

Файл mail.local.php исключён из Git и из сборки хостинга. Пароль не должен попадать в HTML, JS, README или GitHub. Альтернатива файлу — серверные переменные `OMEGA_SMTP_PASSWORD`, `OMEGA_SITE_ORIGIN`, `OMEGA_MAIL_ENABLED=1`.

GET /api/request.php возвращает только доступность обработчика и CSRF-токен, не отправляет писем. POST после серверной проверки вызывает SMTP. Не выполняйте POST и не нажимайте отправку формы для проверки до отдельного разрешения заказчика. Текущие проверки проекта не отправляют заявки.

## Что предусмотрено

Обязательные параметры, e-mail, телефон и отдельное согласие; ограничение размера данных; Origin и CSRF; защищённая сессия; honeypot; ограничение частоты внутри сессии; защита от повторной отправки по requestId; UTF-8; таймаут; сохранение полей при ошибке. SMTP принимает только фиксированный адрес компании. Подтверждение успеха появляется после принятия письма SMTP, а не по нажатию кнопки. Оно не гарантирует попадание во входящие вместо спама.

В сессиях нет текста заявки: только технические токены, идентификатор, контрольная сумма и состояние отправки. Технические файлы очищаются при обращении по истечении часа. Письма и рабочие копии удаляет компания в соответствии с политикой.

Статическая публикация ChatGPT Sites служит для просмотра интерфейса: PHP она не исполняет. Рабочий обработчик входит в пакет для российского хостинга. До настройки там форма не покажет ложный успех.

Перед приёмом реальных данных компания должна проверить фактические сроки удаления писем, доступ сотрудников, хостинг и необходимые обязанности оператора. Политика и согласие подготовлены для заявок, но технический код не заменяет эти действия организации.
