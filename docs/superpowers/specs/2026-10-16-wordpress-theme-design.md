# Тема WordPress «Омега Комплект»

Цель — устанавливаемый ZIP классической PHP-темы с текущим дизайном и интерактивностью. Основание: прямой запрос пользователя подготовить тему сейчас, а плагин и редактирование контента добавить следующим этапом.

## Решения

- Классическая тема подходит существующей разметке и сохраняет её геометрию. Блочная тема потребовала бы отдельной переработки компонентов; упаковка одной HTML-страницы не даёт пригодной архитектуры шаблонов.
- Исходники: `wordpress/omega-komplekt/`. Статический `dist/` и текущая публикация Pages остаются самостоятельными.
- `functions.php` загружает небольшие модули `inc/`: setup, assets, helpers, content, documents, integrations. Секции главной и общие элементы находятся в `template-parts/`.
- WordPress 6.6+, PHP 8.1+. Локальные стили, фотографии и шрифты; штатные hooks и enqueue API; поддержка дочерней темы и панели администратора.
- Главная работает сразу после активации. Общие шаблоны page, single, index, archive, search и 404 выводят штатный контент WordPress.
- Политика и согласие доступны сразу через разрешённый query var `omega_document`. Если существуют опубликованные страницы с соответствующими slug, используются их permalinks и page templates. Активация не создаёт и не перезаписывает записи, настройки или страницы.
- Общие контакты и тексты доступны через `omega_theme_content($section)` и фильтр `omega_theme_content`. Главная разбита на самостоятельные секции, без ACF, CPT, настроек или зависимости от будущего плагина.
- Форма сохраняет клиентскую валидацию, маску и модалки. Отправку предоставляет будущий плагин через `omega_theme_request_settings` / JS-адаптер `window.OmegaThemeRequest`. Пустой endpoint не вызывает сеть и не показывает успех. Пароли, SMTP, PHPMailer и бизнес-логика заявок в тему не входят.

## Контракт интеграции

`omega_theme_asset($path)` возвращает URI ресурса с поддержкой дочерней темы. `omega_theme_anchor($id)` возвращает якорь на главной либо полный URL главной с якорем. `omega_theme_document_url($name, $fragment = '')` работает с обычными и вложенными установками, plain и pretty permalinks.

`omega_theme_content($section)` возвращает массив defaults; фильтр принимает `(array $content, string $section)`. Фильтрация контента не должна выполнять запросы или хранить секреты. Вывод текста экранируется, ограниченная разметка пропускается через `wp_kses_post`, URL — через `esc_url`.

Настройки транспорта: `['endpoint' => '', 'nonce' => '']`. По умолчанию отправка отключена. Плагин может зарегистрировать same-origin REST endpoint и вернуть настройки фильтром либо предоставить JS-адаптер. Ответ успеха принимается только с `ok: true`, `status: 'accepted'` и совпадающим `requestId`. Соглашение полей и ответственность плагина описываются в документации.

## Проверки и результат

1. Реальный локальный WordPress, активация темы, standalone и subdirectory URL, WordPress hooks, native page fallback и query documents, дочерняя тема и admin bar.
2. Главная, политика, согласие, обычная страница и 404 на 1280, 768, 360 и 320 px; меню, модалки, Cookie, таблица шага зуба, маска и локальная валидация. API и любые POST заблокированы, отправки заявок и почты запрещены.
3. PHP syntax, отсутствие битых ресурсов/JS-ошибок, проверка ZIP: один корневой каталог темы, style.css/index.php/functions.php, лицензии, screenshot; отсутствие исходных архивов, QA, Git, конфигурации SMTP и секретов.
4. ZIP темы в корне пользовательской рабочей папки и инструкция установки с картой будущего подключения плагина.
